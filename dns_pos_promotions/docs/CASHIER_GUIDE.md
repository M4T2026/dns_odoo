# DNS Promotions — Cashier Guide

Automatic promotions are calculated from the product's current base sale price when items are added or quantities change. Promotional pricelists are not used.

- Add eligible products normally. The order line shows the applied promotion and saving.
- Bundles only count in whole sets, and the order splits so you can see it. "Any 3 for $5" with 5 items shows two lines: **3 for $5**, then **2 at the normal price**. Add a sixth and the second line becomes another bundle. The spare items are never part-discounted while they wait.
- A calculated promotional line is protected from manual price/discount editing. Remove the promotion or recalculate the order first.
- If promotion data changes while an order has items, finish or discard that order. Its saved snapshot remains unchanged. The new promotion version loads automatically for the next empty order.
- Cached offers are checked against their local end time, so an offline till will not begin applying an expired offer.
- Refund lines retain the original promotion ID, rule, base-price snapshot, allocation, and saving for audit purposes.

If an expected discount does not appear, confirm the store, schedule, and qualifying quantity, then ask a Promotion Manager to check the conflict queue.
